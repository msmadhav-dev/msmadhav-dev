<summary><b>Bioshield Healthcare</b> — Pharmaceutical Commerce Platform</summary>

<br />

**Overview**

A modern pharmaceutical commerce platform focused on seamless medicine ordering, healthcare product delivery, referral management, and customer engagement.

**Description**

Bioshield brings the clarity of a modern storefront to a category that usually feels clinical and dated. Product discovery, cart flow, and checkout are built to stay fast and legible on low-end devices, while referral management gives the business a compounding growth channel rather than a one-off transaction funnel.

**Engineering Notes**

The application is structured around a Next.js App Router frontend with server components handling catalogue rendering, keeping client bundles small on product-heavy pages. Prisma sits over PostgreSQL as a type-safe data layer, with the schema modelling products, orders, referral relationships, and customer records as distinct domains. Supabase handles authentication and storage, so session logic and media delivery stay outside the application server.

<details>
<summary><b>CodePilot</b> — Rule-Based Code Analysis Platform</summary>

<br />

**Overview**

A rule-based full-stack code analysis platform that automates syntax validation, intelligent auto-corrections, documentation generation, code formatting, quality scoring, and performance benchmarking.

**Description**

CodePilot is deliberately built **without AI APIs**. Every result is deterministic and reproducible — the same input always produces the same output, with no inference cost, no network dependency, and no hallucinated suggestions. It's an argument that a large share of "AI developer tooling" is better served by compilers and grammars.

**Engineering Notes**

Analysis runs through Python's own compiler for syntax validation, with Tree-sitter providing concrete syntax trees for structural inspection and auto-correction. Documentation generation uses NLP template matching against parsed AST nodes rather than generative text, and formatting delegates to industry-standard tools so output matches ecosystem conventions. Quality scoring and benchmarking run as separate passes over the same parse tree, which avoids re-parsing and keeps analysis fast on large files.

| Category | Details |
|---|---|
| **Type** | Developer Tooling / Static Analysis Platform |
| **Stack** | Python · Tree-sitter · NLP Template Matching · Standard Formatting Toolchain · Full Stack Web Interface |
| **Architecture** | Multi-pass pipeline: compile-based validation → Tree-sitter AST → correction, documentation, formatting, and scoring passes |
| **Performance** | Single-parse, multi-pass design with no external inference calls — fully local and deterministic |
| **Scalability** | Language-agnostic Tree-sitter grammars allow new languages to be added without changing the pipeline |
| **Status** | Active |
| **Project Page** | [msmadhav.com](https://www.msmadhav.com/) |

A large-scale map modification for Euro Truck Simulator 2, built entirely as a solo project over two years.

A project of this size is fundamentally an asset and consistency problem. Blender handled custom asset creation; the map itself was assembled, tested, and tuned as a single evolving world.

## Development Philosophy

> Software should be as considered on the inside as it looks on the outside.

| Principle | How It Shows Up In My Work |
|---|---|
| **Clean Architecture** | Clear boundaries between UI, domain logic, and data access — so features can change without cascading rewrites |
| **Scalable Systems** | Normalized data models, stateless services, and externalized auth/storage from day one, not after the first bottleneck |
| **Performance** | Treating bundle size, render cost, and query shape as design constraints rather than post-launch cleanup |
| **UI/UX** | Interfaces designed before they're implemented — motion, hierarchy, and feedback are part of the spec |
| **Maintainability** | Predictable structure, typed contracts, and code that reads clearly six months later |
| **Accessibility** | Semantic markup, keyboard paths, and contrast treated as baseline requirements |
| **Developer Experience** | Fast local feedback loops, consistent tooling, and deterministic builds |
| **Continuous Learning** | Choosing projects that force me into unfamiliar territory, then shipping something real with it |
